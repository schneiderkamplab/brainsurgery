# Real-checkpoint preservation protocol

Protocol identifier: `eacl2027_real_preservation_v1`

Status: frozen before the first reported run

## Purpose

The synthetic correctness protocol provides hand-verifiable independent
oracles for individual transformations. This complementary protocol tests the
no-unintended-change property across every tensor in three real checkpoint
layouts already used by the paper and usability study:

- GPT-2 124M, single-file safetensors;
- OLMo 1B, indexed sharded safetensors;
- Pythia 1B, single-file safetensors.

Axon and Synapse are excluded.

## Operation

Each plan performs `scale_` by exactly `1.0` on one named floating-point tensor.
This explicit no-op is necessary because the CLI selects its output model from
mutating transform destinations and rejects output plans with no mutating
transform. The expected logical state is the independently loaded input state.

The selected tensors and pinned Hugging Face revisions are frozen in
`real_cases.yaml`.

## Primary endpoints

For every checkpoint:

1. Hugging Face download metadata identifies the frozen revision;
2. the CLI exits successfully;
3. the output tensor-name set equals the input name set;
4. every output tensor has the same shape and dtype as the input;
5. every output tensor is byte-identical to the independently loaded input;
6. every tensor outside the one-element write-set is byte-identical;
7. every source checkpoint data/index file remains byte-identical.

All endpoints must pass for all three checkpoints. There is no numerical
tolerance or aggregate-majority criterion.

## Independence and claim boundary

The runner loads and hashes inputs and outputs directly with safetensors and
PyTorch. BrainSurgery is invoked only through its public CLI. The expected
output is never generated by BrainSurgery.

This experiment demonstrates exact tensor-state preservation for one explicit
identity operation across the enumerated checkpoint formats and revisions. It
does not prove correctness for arbitrary transformations, metadata/sidecar
preservation, or every model format. Runtime from this Mac run is not a systems
performance result.

## Reproducibility

The runner records the Git commit, relevant-path cleanliness, exact model
revisions, source-file and tensor hashes, environment, plans, commands, captured
CLI logs, comparisons, and compact summary. Raw checkpoint outputs are written
only beneath `log/revision_tests/<run_id>/`.
