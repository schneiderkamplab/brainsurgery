\section{Graph IR Lowering}

\paragraph{Input and output.}
Graph lowering consumes a flat, closed, fully typed Axon AST and produces an
in-memory typed Graph IR program.

\paragraph{Contract.}
The lowering stage translates Axon definitions to graph modules, bind
statements to graph nodes, multi-output expressions to structured graph
outputs, and path literals to structured graph paths.  It preserves operand
types, output types, constraints, constants, and module boundaries needed by
backends and later graph-level analysis.

\paragraph{Exclusions.}
Lowering does not accept surface constructs such as \code{scope}, \code{for},
or statement-level \code{if}.  It also does not rewrite primitive calls into
legacy string-based callee forms.

\paragraph{Rationale.}
Graph IR replaces the old serialized graph contract.  The compiler should pass
typed structured objects to backends rather than relying on YAML-shaped
dictionaries or render/parse cycles.

\paragraph{Formal view.}
Lowering is a homomorphism from typed flat modules to graph modules:
\[
  \mathsf{lower}: A_{\mathrm{flat}}^{\tau} \rightarrow G.
\]
Each flat definition becomes a graph module.  Each flat bind becomes one graph
node with typed operands and typed outputs.  Calls to user definitions become
module-call nodes; calls to primitive wrappers lower to primitive graph ops
only when the source definition is itself a primitive wrapper.

\paragraph{Representation.}
The implementation represents a graph as a \code{GraphProgram}.  A program
contains a tuple of \code{GraphModule} objects, a selected main module, and
program pragmas.  Each \code{GraphModule} has typed input \code{GraphValue}
objects, ordered return operands, optional output names, a sequence of
\code{GraphNode} objects, an optional return type, and symbolic constraints.

A \code{GraphNode} is a typed SSA-style binding.  It has a stable node id, a
\code{GraphOp}, positional input operands, named attribute operands, one or
more typed \code{GraphValue} outputs, the source module name, a result type,
and optional tensor-dimension metadata.  Values are referenced by
\code{GraphValueRef}.  Literals are \code{GraphLiteral}; paths are
\code{GraphPath}; nested atomic graph expressions such as tuples, lists,
ascriptions, binary expressions, and ternary selects are \code{GraphExpr}.
The graph operand type is therefore:
\[
  \mathsf{operand} =
  \mathsf{valueRef} \mid \mathsf{literal} \mid \mathsf{path} \mid
  \mathsf{graphExpr}.
\]

\paragraph{Structured paths and attributes.}
A path is not a backend-specific string.  A \code{GraphPath} stores whether the
path is absolute and stores its parts as a tuple.  Template placeholders such
as \code{\{i\}} remain inside path parts and are validated against lexically
available graph values or dimension symbols.  Keyword arguments lower to graph
attributes whose values are ordinary graph operands, so \code{shape=[B,S,D]},
\code{dim=O}, \code{bias=true}, and \code{path=@@proj} all remain typed
structured data.

\paragraph{Multi-output binds.}
Graph IR keeps multi-target Axon binds as one node with multiple outputs.  If
typecheck2 inferred a tuple return type, each output receives the corresponding
tuple item type.  If it inferred a list return type and the flat program
destructures that list, each output receives the list item type.  This avoids
lowering a natural operation such as
\begin{verbatim}
q, k, v <- Tensor.chunk qkv parts=3
\end{verbatim}
into an artificial list value followed by three unrelated index nodes.

\paragraph{Core and module operations.}
Graph op names preserve the distinction between compiler-core expressions and
ordinary calls.  Binary expressions lower to operations such as
\code{core.binary.+}; ternaries lower to \code{core.select}; aliases and
ascriptions lower to \code{core.alias} and \code{core.ascribe}.  Other op names
refer either to graph modules or to primitive/builtin operations present in the
typed flat Axon program.  The graph validator resolves module calls by name and
checks their actual operands against the callee module inputs.

\paragraph{Example.}
A typed flat bind
\begin{verbatim}
tok <- NN.embedding @@wte input_ids dim=MODEL_DIM
\end{verbatim}
lowers to a graph node whose op is the embedding primitive, whose first operand
is a structured absolute path \code{@@wte}, and whose output type is the
inferred tensor type, e.g. \verb|Tensor[B,S,MODEL_DIM]|.

\paragraph{Multi-output nodes.}
Graph IR preserves multi-output structure.  A flat destructuring bind such as
\begin{verbatim}
q, k, v <- Tensor.chunk qkv parts=3
\end{verbatim}
can lower to a single graph node with three outputs rather than a synthetic
list plus three unrelated index operations.

\paragraph{Metadata for later optimization.}
Because \code{GraphValue}, \code{GraphValueRef}, \code{GraphExpr}, and
\code{GraphNode} all carry type information, graph-level passes can inspect
tensor ranks, symbolic dimensions, optionality, path templates, and operation
boundaries without reparsing Axon source.  This is the intended substrate for
future safe graph optimizations and backend-specific kernel selection.
